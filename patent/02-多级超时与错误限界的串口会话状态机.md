# 专利点 2：逐级超时 + 错误计数限界的多级串口会话状态机

> 对应《专利思路.md》第一部分第 2 点。**申请优先级：强，明确优于 Qt 原版，建议作主权利要求（或与第 3 点合并）。**

## 撰写边界

- 连接链/获取链的具体报文号是设备协议内容，权利要求中一律用位置化描述（"链首命令""第 i 级请求命令""对应响应帧"）。
- 发明点在"每一级独立超时 + 错误计数限界 + 分级重发 + 短应答终止语义"这四个机制及其组合，不涉及协议字节本身。

## 一、技术问题

工业串口设备可能断电、拔线、不应答，主站的多级会话（先请求 A 参数、收到后再请求 B 参数……逐级级联）在异常下必须**有界收敛**：要么推进、要么重试、要么明确报错。Qt 原版状态机存在三个缺陷：

1. **只有链首一级有超时**：Qt 仅对连接链第一级（35 号报文）设 3333ms 超时（m_timer12）；后续级一旦设备不应答，状态机永久停在等待状态，界面假死。
2. **获取流程对短应答（裸 E5）无处理**：设备对获取命令只回短应答（"已确认但无数据"）时，Qt 状态机无限停在等待末帧（50 号帧）上，仅靠一个 999ms 界面定时器"假装"刷新。
3. **超时出口两难**：Qt 获取流程超时只弹错误框不重试（用户只能手动重来）；若简单改成"超时即重发"，又可能因设备持续不应答而无限循环。

## 二、创新点

1. **链式逐级超时**：会话链的**每一级**都有独立的响应超时（3333ms），用单一定时器沿链逐级重置复用；任何一级设备沉默都会在有限时间内被检出，而不是只有链首一级。

2. **统一错误计数限界**：超时、错误帧、连接期短应答/回显应答等**全部异常输入统一计入一个错误计数器**，达到阈值（≥5）即终止会话并报通信错误——为所有重试路径提供统一的有界性保证。

3. **分级差异化重发策略**：不同会话阶段的重试对象不同——连接期重发链首命令（35 号），获取期重发获取链首命令（37 号），重发动作与阶段绑定而非写死。

4. **获取期短应答的"确认无数据"终止语义**：获取阶段收到短应答，判定为"设备已确认命令且无数据帧可回"，置结束标志、**正常结束会话**并刷新已收到的数据——把 Qt 的"无限等待"改造成一个有明确语义的收敛出口。

5. **有界收敛设计准则（方法本质）**：状态机满足"任一输入事件 ∈ {推进链路 / 计错重发 / 终止会话}"三选一，不存在任何使会话无限等待或无限重发的输入序列。

## 三、具体实现方式

### 3.1 状态变量

| 变量 | 含义 | 用途 |
|---|---|---|
| `Down` | 会话模式标识（连接模式 / 获取模式 / 空闲） | 异常输入按模式分流 |
| `Connect_Index` | 当前链路级号 | 决定"下一级该发什么、该期待什么" |
| `ErrorCounter` | 全局错误计数 | 所有异常输入的统一限界（≥5 终止） |
| `RX_Msg_End` | 数据结束标志 | 获取期短应答/末帧设置，控制链路提前结束 |
| `Msg_Len` | 已收数据长度 | 已收数据刷新 |
| `stageTimer` | 单一级超时定时器 | 沿链逐级重置复用 |

### 3.2 会话链与发送表

- **连接链（4 级）**：发链首命令 → 期待响应 1 → 发第 2 级命令 → 期待响应 2 → 发第 3 级命令 → 期待响应 3 → 发第 4 级命令 → 期待响应 4 → **会话完成**（置界面状态、进入空闲模式）。
- **获取链（4 级，其中一级按源程序连发两次）**：发链首命令 → 期待响应 1 → 发第 2 级命令 → 期待响应 2 → 再发第 2 级命令 → 期待响应 2 → 发第 4 级命令 → 期待响应 4 → 会话完成（重复连发是源程序原样行为，属"等价保留"）。

发送表为"级号 → 命令"的查表结构；期待表为"当前级号 → 期望响应报文号"。

### 3.3 定时器生命周期（链式逐级超时）

- 每发送一级命令 → `startStageTimer()`：先清除旧定时器，再启动新的 3333ms 定时器（**单定时器沿链重置复用**，等价于每级独立超时）。
- 每收到任何数据帧 → 立即清除定时器（本级等待结束）。
- 定时器触发 → 按当前模式进入对应超时出口（见 3.4）。

### 3.4 异常输入处置表（核心规则集）

| 输入事件 × 会话阶段 | 动作 | 计数 | 出口 |
|---|---|---|---|
| 数据帧，报文号为当前级期望 | 推进级号，发下一级命令，重启定时器 | — | 推进 |
| 数据帧，报文号未知 | 计数，级号归零，重发链首命令 | ErrorCounter++ | 重试 |
| 数据帧，报文号已知但非当前级期望 | 级号归零，重发链首命令（受计数阈值约束） | — | 重试 |
| 短应答（连接期） | 计数，级号归零，重发链首命令 | ErrorCounter++ | 重试 |
| 回显应答（连接期） | 计数，级号归零，重发链首命令 | ErrorCounter++ | 重试 |
| 短应答（获取期） | 置数据结束标志，**正常结束会话**，刷新已收数据 | — | 收敛（成功） |
| 回显应答（获取期） | 忽略（仅记录日志） | — | 继续等待 |
| 级超时（连接期） | 报通信错误，终止会话 | — | 收敛（报错） |
| 级超时（获取期） | 计数，级号归零，重发链首命令 | ErrorCounter++ | 重试 |
| 任何错误计数 ≥ 5 | 报通信错误，终止会话 | — | 收敛（报错） |

### 3.5 核心循环伪代码

```
发链首命令 → 启动 3333ms 级定时器
循环（事件驱动：帧 / 短应答 / 超时）：
  数据帧且为当前级期望 → 推进级号，清定时器，发下一级命令，重启定时器
  数据帧但报文号未知   → ErrorCounter++，级号归零，重发链首命令
  短应答（连接期）     → ErrorCounter++，重发链首命令
  短应答（获取期）     → 置结束标志，正常结束会话
  级定时器超时（连接期）→ 报通信错误，终止
  级定时器超时（获取期）→ ErrorCounter++，重发链首命令
  每次重试前检查：ErrorCounter ≥ 5 → 报通信错误，终止
```

### 3.6 通信错误出口

终止时清除定时器、复位会话标志，但**保持串口链路打开**，并给出原因与可操作提示（"装置未连接、未上电或波特率不符时会出现此错误；可重试或进入离线模式"）——区别于 Qt 直接退出程序。

## 四、与 C++（Qt 原版）方式的不同点

| 维度 | Qt 原版 | 本方案 |
|---|---|---|
| 超时覆盖 | 仅链首一级设 3333ms；后续级设备沉默则**永久卡死** | **每一级**独立 3333ms，单定时器沿链重置复用 |
| 获取期短应答 | 无任何处理，状态机停在等待末帧，靠 999ms 界面定时器掩饰 | 判定"已确认且无数据可回"→ 置结束标志、正常收敛并刷新数据 |
| 获取期超时 | 只弹错误框、不重试 | 重发获取链首命令并计数；计数达阈值后终止——既不卡死也不无限循环 |
| 错误计数语义 | 仅对部分错误帧计数 | 超时/短应答/回显应答/未知帧**统一计数**，≥5 统一终止出口 |
| 错误后行为 | 弹出错误并退出程序 | 保持串口打开 + 给出原因与操作建议，可立即重试 |
| 收敛性 | 存在无限等待状态（无界不收敛） | 任一输入事件 ∈ {推进 / 计错重发 / 终止}，**有界收敛** |

## 五、技术效果

- 设备断电、拔线、不应答时，链路在**每一级最多 3.3s 内**被检出，重试最多 5 次后**明确报错**——不会死循环、不会假死。
- 设备"确认但无数据"这一真实工况有了确定的正常出口（获取期短应答终止语义），而非无限等待。
- 状态机行为可模拟验证：无真机、无浏览器环境下用 mock 截获发出的每个字节，验证正常序列与全部异常分支（对应 `state-machine-test.js`）。

## 六、权利要求要点建议

**主权利要求（方法）**：一种多级串口会话的状态机控制方法，其特征在于：
- 将交互会话划分为顺序级联的多个阶段，主站在每阶段发送一请求命令并等待对应响应帧；
- **每一阶段**分别设置独立的响应超时定时器；
- 任一级超时或收到错误应答时，按当前会话模式选择对应的链首命令重发，并将本次错误计入全局错误计数；
- 全局错误计数达到预设阈值时，终止会话并报通信错误；
- 数据获取类会话收到短应答时，判定为"设备已确认且无数据可回"，设置数据结束标志并正常结束会话。

**从属权利要求方向**：阈值取 5；错误应答包括单字节短应答、回显应答、未知报文号数据帧；连接类会话重发连接链首命令、获取类会话重发获取链首命令；定时器为单实例沿链逐级重置复用（超时时长 3333ms）；终止后保持通信链路打开并输出可操作提示。

**与第 3 点的关系**：本点覆盖会话级（连接/获取链路）容错；第 3 点覆盖命令级（单条对话框命令）应答匹配——两者可在同一件专利中作"一种串口通信容错与应答匹配方法"的主从权利要求组合。
