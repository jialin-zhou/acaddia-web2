# 专利点 1：跨语言协议软件的字节级等价移植与验证方法

> 对应《专利思路.md》第一部分第 1 点。**申请优先级：最强、最独特，建议作主权利要求。**

## 撰写边界（务必注意）

- 设备的通信协议本身（68 L L 68…16 帧格式、报文号表、补零压缩算法）属于设备厂家的协议，**不能作为发明点**。
- Qt 原版为在先成果，属现有技术；**发明点只写网页版相对 Qt 版的改进 + 移植方法论本身**。
- 权利要求中协议特征一律用位置化/角色化描述（"链首命令""数据帧""短应答""压缩预处理"），不出现具体帧字节与报文号。

## 一、技术问题

把 C++ 串口协议软件移植到 JavaScript 后，数值语义漂移会导致与设备交互不再逐字节一致。两类根因：

1. **语言语义差异**：C++ 与 JS 在类型转换、整数除法、位宽、字节序上的默认行为不同，逐行"直译"代码会静默产生错误字节——编译不报错、界面不报错，只有设备能察觉。
2. **缺乏可回归的正确性判据**：移植"对不对"原本只能靠上真机、靠人眼对照字节流，没有可自动重复执行的判定谓词；后续每改一处代码都可能引入新漂移而无人知晓。

本项目实际踩中的语义陷阱（即映射规则集的覆盖范围）：

| # | C++ 原语 | 陷阱 | 常见错误做法 | 正确 JS 等价映射 |
|---|---|---|---|---|
| 1 | `static_cast<ushort>(float × N)` | 截断（向零），非四舍五入 | `Math.round()` | `Math.trunc(float × N)` |
| 2 | `static_cast<uchar>(v / 25)` | 先整数除法、再 8 位截断 | 直接 `/`（得浮点） | `(Math.floor(v / 25)) & 0xFF` |
| 3 | `float` 直接赋给 `unsigned short` | 赋值即截断 | `Math.round()` | `Math.trunc()` |
| 4 | 个别字段大端序（主界面 Line1@20） | 与协议其余字段小端序相反 | 统一按小端读 | 该字段单独按大端拼接 |
| 5 | 毫秒字段接收 3 字节 / 发送 4 字节 | 收发字节数不对称 | 收发对称处理 | 分别按 3 字节读 / 4 字节写 |
| 6 | 日期基准 1984-01-01 的偏移 | 不同报文加减规则不同 | 统一减 1 或不减 1 | 解析 A 报文 days−1、解析 B 报文不减 1、发送 days+1 三处分别处理 |
| 7 | `& 0xFF` 等无符号窄化 | JS 无 8 位无符号类型 | 直接算术运算 | 逐处 `& 0xFF` / `>>> 0` |
| 8 | C++ 整数除法 `/` | JS `/` 永远得浮点 | 直接 `/` | `Math.floor()` |
| 9 | 打包前补零压缩预处理 | 源数据长度 ≠ 实发长度 | 忽略压缩步骤 | 逐行移植统计与截断规则（如 41→40、90→89、4→3、7→6 字节） |

## 二、创新点

1. **面向协议软件的跨语言数值语义等价映射规则集**：把"C++ 表达式 → JS 表达式"的等价关系整理为显式规则集（上表九类），移植时逐表达式套用规则，而不是逐行"直译"代码。规则覆盖类型转换、整数除法、位宽截断、字节序、日期基准、压缩预处理等全部协议语义。

2. **三向数据流等价验证模型**：把"移植一致性"分解为三个可自动判定的数据流，任一方向不等价即判移植失败——
   - **A. 下行流（网页→装置）**：网页组装并发送的数据与源程序组帧结果逐字节比对；
   - **B. 上行流（装置→网页）**：装置发来的帧，网页的解析与展示结果与源程序比对；
   - **C. 内部流转流（网页内部）**：注册表→显示、文件→界面→下发、标幺→换算等状态流转与源程序内部流转比对。

3. **期望值独立推导 + 源码行号溯源**：所有测试期望值由 Qt 源码公式**手工推算**，并在测试注释中标注出处（文件+行号，如 `Dlg_TQCS1.cpp 220-236 行`、`Dlg_AD1.cpp 936-972 行`）。期望值不依赖被测实现，杜绝"照新实现抄期望"导致的测试自证。

4. **无浏览器分层的可测架构**：把纯数据层（打包/解析/显示计算）与 DOM 层强制分离，纯数据层可在 Node.js 中直接加载执行验证——协议正确性与浏览器、真机、设备全部解耦，验证可进 CI。

5. **差异分类管理制度**：移植中发现的每处行为差异必须归类并留档：
   - **① 等价保留的怪癖**（设备兼容性所必需：补零压缩、连续重复发送、日期 ±1、毫秒 3/4 字节不对称等）——逐字节原样保留；
   - **② 源程序缺陷**（未初始化变量、控件接线错误、漏赋值、历史遗留常数等）——按意图修正，并在公开文档中逐条记录修正理由。
   分类决策形成可审计的移植决策日志，是"等价"主张的证据链。

## 三、具体实现方式

### 3.1 分层移植架构

```
app/js/
├── protocol.js   # 组帧/解帧层（移植自 TeleProcess.cpp：TelePack/TeleUnpack）
├── store.js      # 全局状态 + 数据注册表（含 4 字节头）
├── core.js       # 纯数据层：打包/解析/显示计算，无 DOM，可测
├── serial.js     # 串口管理 + 通信状态机（移植自 new1Dlg.cpp）
└── app.js + dlg-*.js  # DOM 薄层（各 Dlg 对话框移植）
```

移植单元 = 源程序中的**函数**（TelePack、TeleUnpack、各对话框打包/解析分支），而非界面或文件。每个 JS 模块头部注释声明对应的 Qt 源文件。

### 3.2 语义映射规则的落地形式

- **统一入口函数**：`readShortLE / readInt24LE / readInt32LE / writeShortLE` 集中提供位宽与字节序入口；大端字段单独手写拼接。
- **逐处注释**：每处截断（`Math.trunc`）、整数除法（`Math.floor`）、窄化（`& 0xFF` / `>>> 0`）旁注释对应 C++ 原语，保证可审计。
- **压缩算法逐行移植**：打包函数逐行对照源程序（拷贝至 0x00 → 零计数减一 → 计数未耗尽则补零继续，否则丢弃后续；校验和只累加实际拷贝的字节）。

### 3.3 三向数据流等价验证体系（177 项检查）

测试位于 `app/test/`，三个套件一键运行（`node test/run-all.js`），共 **177 项检查**：

| 套件 | 方向 | 覆盖内容（举例） |
|---|---|---|
| `protocol-test.js` | A（组帧/解帧字节级） | 所有读取命令帧、补零压缩（41→40 / 90→89 / 4→3 / 7→6）、校验和、E5 前缀、裸 E5、0xA2、校验失败丢弃 |
| `state-machine-test.js` | A+C（状态机） | 连接序列与获取序列发出的**每个字节**、A2 应答、异常帧重发、错误计数 |
| `data-flow.test.js` | A+B+C（三向全覆盖） | 见下 |

`data-flow.test.js` 的 A/B/C 具体内容：

- **A. 网页 → 装置**：同期参数 41 字节缓冲逐字节 + 完整帧（含手算 CRC）；AD 参数 90 字节 DATA（两分支默认值、整数除法+截断、SecVNV 保留）；通道校准（通道号公式、除数序列、4→3 字节）；时间设置（7→6 字节）；同期命令（补零压缩）。
- **B. 装置 → 网页**：各响应报文解析（缩放、取反、回填、×25、毫秒 3 字节不对称、日期减 1 与不减 1 的差异、DEC/HEX 显示补齐位）；主界面显示计算（大端、负值补码、DC 单位随选择位、基准值翻倍）；消息列表解析（编号偏移、日期偏移、毫秒拼装、事件符号）。
- **C. 网页内部流转**：连接响应 → 注册表 → 界面状态；93 字节文件 → 界面 → 打包下发**回环**；标幺 → 显示换算；参数获取→应用回环；时间设置打包→解包回环（含 ≥2²⁴ 毫秒截断）。

### 3.4 无浏览器回归基础设施

- 纯数据层文件在 Node.js 中以脚本方式直接加载（无需打包器）；DOM 以 mock 桩代替（`getElementById/createElement` 返回空实现）；`navigator.serial` 置空；串口写函数以数组截获——状态机测试在**无浏览器、无真机、无设备**下验证发出的每个字节。
- 每项检查输出 PASS/FAIL 与十六进制明细，失败时打印期望/实际对比，可直接定位漂移字节。

### 3.5 闭环流程（方法权利要求的主干步骤）

1. 建立源语言→目标语言的数值语义映射规则集；
2. 按协议功能将源程序分层移植（移植单元=函数）；
3. 对每一层生成三向数据流等价检查，期望值按源程序公式手工推算并标注源码位置；
4. 在无目标运行环境依赖的测试环境中自动执行全部检查；
5. 对未通过项，判定属于"映射规则遗漏"还是"源程序缺陷"：前者补充映射规则，后者按意图修正并记录；
6. 全部通过后，输出"与源程序逐字节等价"的结论，且该结论可持续自动回归。

## 四、与 C++（Qt 原版）方式的不同点

| 维度 | Qt 原版（C++）的开发/验证方式 | 本方法（Web 版移植过程） |
|---|---|---|
| 正确性判据 | 无自动化判据；靠上真机调试、人眼对照字节流 | 三向数据流 177 项检查，自动判定通过/失败 |
| 期望值来源 | 无独立期望值 | 按 Qt 源码公式手工推算，标注文件行号，独立于被测实现 |
| 回归能力 | 改一处需重新上机验证 | 一条命令全量回归，可进 CI |
| 验证环境 | 需编译、需真机、需设备 | 无浏览器、无设备即可验证（串口字节由 mock 截获） |
| 语义差异处理 | 不存在（本身就是 C++） | 显式映射规则集，逐表达式转换并留注释 |
| 源程序缺陷处置 | 原样携带（未初始化变量、控件接线错误、漏赋值） | 差异分类：怪癖等价保留 / 缺陷按意图修正并留档 |
| 移植决策记录 | 无 | 每处差异在公开文档留档，形成可审计的移植决策日志 |

## 五、技术效果

- 移植前后与设备的交互**逐字节一致**，且一致性**可证明、可自动回归**（177 项检查全部通过）。
- 验证过程抓出并修正 3 处真实漂移：`static_cast<ushort>` 截断而非四舍五入、`/25` 整数除法+uchar 截断、SecVNV 未在解析/打包间保留——证明方法对语义漂移有实际检出能力。
- 验证不依赖设备、不依赖浏览器，可在任何有 Node.js 的机器上复现。

## 六、权利要求要点建议

**主权利要求（方法）**：一种跨语言移植的串口通信软件字节级一致性验证方法，其特征在于包括以下步骤：
- 建立源语言到目标语言的数值语义等价映射规则集，至少覆盖截断式类型转换、整数除法、位宽截断、字节序、日期基准修正、数据压缩预处理；
- 将待移植软件按协议功能分层移植；
- 对每一层分别生成下行组帧流、上行解析展示流、内部状态流转流的等价性检查，检查期望值按源程序公式独立推算并标注源码位置；
- 在无目标运行环境依赖的测试环境中自动执行全部检查；
- 对未通过项按"语义映射遗漏"与"源程序缺陷"分类处理（前者修正映射规则，后者按意图修正并记录），直至全部通过，输出等价性结论。

**从属权利要求方向**：映射规则的具体条目（截断、整数除法+窄化、大端字段、3/4 字节不对称、日期基准 ±1、补零压缩）；三向数据流的定义与检查内容；期望值标注格式；无浏览器测试环境（DOM 桩、字节截获）；差异分类与留档步骤。

**系统权利要求**：与专利点 5 的浏览器测控终端系统合并（见 05 文档）。
