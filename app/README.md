# ACAD DIA Web 版

纯 HTML/CSS/JS 三件套实现的测控终端（对应 Qt 版 ACAD DIA），无需 npm / 构建工具。
界面基于 **Bootstrap 5**（已本地化到 `vendor/` 目录，无需网络/CDN，发给别人直接打开即用）。
串口通信使用 **Web Serial API**（Chrome / Edge 支持），交互逻辑逐行对照 Qt 版移植。

## 运行方式

任选其一：

1. **直接打开**：用 Chrome/Edge 打开 `index.html`（file:// 协议在 Chrome/Edge 下属于安全上下文，Web Serial 可用）
2. **本地服务器**（推荐，最稳妥）：
   ```
   cd app
   python -m http.server 8080
   ```
   然后浏览器访问 http://localhost:8080

> 浏览器必须是 Chrome 或 Edge（需要 Web Serial API）。首次点击 Connect 会弹出串口授权窗口。


## 日志模块（js/log.js）

页面底部有可折叠的"通信日志"面板，所有串口收发、状态机流转、错误都带毫秒时间戳记录：

- **面板按钮**：清空 / 导出（下载 .log 文件，含未捕获异常，排查问题时可替代手动复制控制台）/ 收起
- **级别过滤**：面板下拉选择 DEBUG/INFO/WARN/ERROR；也可用 URL 参数 `?log=warn` 启动时过滤，或运行时在控制台执行 `Logger.setLevel('warn')`
- **收发明细**：TX/RX 均记录完整帧十六进制（如 `68 04 04 68 00 09 80 25 AE 16`）与状态机快照（`Down/idx/err/msgEnd/msgLen`），便于对照 Qt new1Dlg 状态机定位问题

## 数据流等价性测试（对照 Qt 版）

> 测试要求：数据相关的一切流转都必须与 Qt 版完全一致——
> 网页发给装置的数据 = Qt 打包的字节；装置发给网页的数据 = Qt 的接收与展示；
> 网页内部流转 = Qt 的 ValidData / DIM_public / DC_V_I_select 等内部流转。

运行（需要 Node.js）：

```
node test/run-all.js        # 一键运行全部 3 个套件（共 177 项检查）
node test/data-flow.test.js # 仅数据流等价性套件
```

| 套件 | 覆盖内容 |
|---|---|
| `protocol-test.js` | 组帧/解帧字节级：所有读取命令帧、补零压缩（41→40 / 90→89 / 4→3 / 7→6）、校验和、E5 前缀、裸 E5、0xA2、校验失败丢弃 |
| `state-machine-test.js` | 通信状态机：连接序列 35→34→33→32→37→36→47→48 发出的每个字节、A2 应答、主界面获取序列 37→47→47→49、连接期裸 E5/未知帧重发 35、错误计数 |
| `data-flow.test.js` | 三向数据流（见下） |

`data-flow.test.js` 三类数据流（期望值均按 Qt 源码公式手工计算，注释标注 Qt 文件行号）：

- **A. 网页 → 装置**：同期参数 41 字节缓冲逐字节 + 完整帧（含手算 CRC）；AD 参数 90 字节
  DATA（16384/8192 两分支默认值、OCT 整数除法+uchar 截断、SecVNV）；通道校准
  （通道号公式、除数 57.74/5/1/2.5/10、FormChang 十六进制、4→3 字节）；时间设置
  （7→6 字节、0 计数）；同期命令（[55 AA] / 1 字节类型）
- **B. 装置 → 网页**：34/32/48/28/46/50 各响应解析（缩放、取反、synchron2 回填、
  oct ×25、毫秒 3 字节不对称、日期减 1 与不减 1 的差异、DEC/HEX 显示补齐位）；
  主界面 AD 计算值显示（Line1 固定除 16384、大端、负值补码、DC 单位随 select、
  DIM_public 翻倍、勾选控制）；消息列表解析（MsgID-32768、日期+1、毫秒拼装、Event 符号）
- **C. 网页内部流转**：连接流程 32 响应 → AD1_ValidData → Current_Style=[55]、
  DC_V_I_select 全 1；93 字节文件 → 界面 → 打包下发回环；AD 下载 → DC_V_I_select
  → 主界面 DC 单位变化；标幺 4000H/2000H → 显示换算；同期参数获取→应用回环；
  时间设置打包→解包回环（含 ≥2^24 毫秒截断）

> 测试曾抓出并已修复的实现问题：C++ `static_cast<ushort>` 是截断而非四舍五入、
> `/25` 是整数除法 + uchar 截断、SecVNV 未在解析/打包间保留——均已按 Qt 语义修正。



- 帧格式：`68 L L 68 | 站址(0) | F1(0x09) | F2(0x80) | 报文号 | 数据 | 累加校验和 | 16`
- 收到数据帧后回单字节 `0xA2`；设备短应答为 `0xE5`（数据帧带 E5 前缀）
- 连接序列：35→34、33→32、37→36、47→48
- 主界面获取序列：37→36、47→48、47→48、49→50
- 报文号表：

| 功能 | 发送 | 响应 |
|---|---|---|
| 同期参数 获取/下载 | 35 / 34 | 34 |
| AD参数 获取/下载 | 33 / 32 | 32 |
| 主界面 AD计算值 | 37 | 36 |
| 角度矢量 | 47 | 48 |
| 通信报文 | 49 | 50 |
| 时间 获取/设置 | 29 / 28 | 28 |
| 通道校准 | 38 | 39（装置实际：`[通道号,0x55]`）／41（Qt 假定）／E5 |
| 同期命令 开出/读取 | 44 / 45 | 46（或 E5） |

- 下载类命令的补零压缩算法（`TelePack` 的 `Zero` 参数）已逐行移植：
  同期参数 41 字节 → 实际发 40；AD参数 90 字节 → 实际发 89；通道校准 4 字节 → 实际发 3；
  同期开出 [55 AA 00] → 实际发 [55 AA]。

## 与 Qt 原版的已知差异（均为 Qt 自身缺陷/无确定行为，已按合理方式处理）

1. **通道校准 DC 模式**：Qt 原代码在 DC 模式下 `Temp_float` 未初始化（未定义行为，实际发送垃圾值）。
   本版按界面填写的校准值下发：零漂校准默认 0mA（校零）、系数校准默认 20mA
   （装置直流量板卡为 4-20mA，系数校准按标称 20mA），均可在表格中编辑。
2. **AD参数 "Primary Current Scaling(OCT)" 输入框**：Qt 原代码把该输入框读进了错误变量，
   导致修改无效（始终按默认 3000 发送）。本版按标签意图正确接线（默认仍为 3000，字节不变）。
3. **AD参数默认值 8192 分支**：Qt 原代码漏赋 C_DC3，本版按意图补齐为 DIM_DCS。
4. **等待方式**：Qt 对话框发送后延时 666/1000ms 再解析（设备响应慢时会显示旧数据）；
   本版改为等待响应帧到达（超时 3333ms 报错），收发字节序列不变。
5. **超时重试**：Qt 只对连接第一级（35 号）设 3333ms 超时，后续级卡死无超时；
   本版对每级均套用 3333ms 超时。获取流程超时会重发 37 并计入错误（Qt 判据
   ErrorCounter>4 报通信错误），错误≥5 次报通信错误停止重试，避免设备不响应时无限循环。
6. **获取流程收到裸 E5**：Qt 对 Down==1005 的 E5 不做任何处理，状态机停在等待 50 号帧上，
   仅靠 OnButtonZjmFetch 的 QTimer::singleShot(999) 刷新界面（已收到的数据照常显示）。
   本版等价处理：设备已确认命令且无数据帧可回 → 置 RX_Msg_End、结束获取并刷新已收到的数据。
7. **通道校准的响应报文号**：装置对 38 号校准命令实际回 **39 号帧 `[通道号, 0x55]`**
   （0x55 为成功状态；实测校准后 32 号帧 AD 参数 C_DC 相应变化）。Qt 分发表中无 39 号
   （Qt 原版同样无法识别、界面看不出成功）。本版登记 39 号帧、校准命令期待 39（兼容 41），
   状态字节 0x55 判定成功。
8. **主界面消息列表**：Qt 当前版本从不请求告警列表（13 号报文被注释），
   故本版消息表格同样为空；解析逻辑已按 Qt 移植（若设备主动发 2/3 号响应会显示）。
9. **Line1 归一除数**：Qt 原代码 Line1 固定除 16899（历史遗留常数），在满量程 4000H
   （16384）的装置上所有 Line1 读数偏低 3.05%（实测 57.74V 显示 55.98V、28.87V 显示 27.99V）。
   本版按装置实际满量程 16384 修正（Line2/DC 仍按 DIM_public，与 Qt 一致）。

## 使用流程（与 Qt 版一致）

1. 打开页面 → 点击 **Connect**（首次会请求选择串口，默认 9600,n,8,1）
   → 自动执行连接序列加载 同期参数/AD参数/AD计算值/角度矢量 → 进入主界面
2. **Offline** = 离线模式（数据清空，直接进入主界面）
3. 主界面：勾选 line1/line2/DC 控制显示；**获取信息** 重新加载全部数据；
   **保存参数/打开文件** 对应 AD 参数的 93 字节 .bin 文件
4. 顶部 9 个按钮打开各功能对话框，行为与原 Qt 工具一致
