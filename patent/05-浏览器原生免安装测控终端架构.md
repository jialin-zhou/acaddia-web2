# 专利点 5：浏览器原生免安装工业测控终端架构

> 对应《专利思路.md》第一部分第 5 点。**定位：单独看不算强发明点，作"系统独立权利要求"包装第 1–4 点，构成"一种基于浏览器的测控终端通信系统"。**

## 撰写边界

- 本点是**系统/产品形态权利要求**，不是方法权利要求；其价值在于把第 1–4 点的方法装入一个"免安装、离线自包含、浏览器直连硬件"的系统里。
- Web Serial API、file:// 安全上下文是浏览器平台公共能力，不是发明点；发明点在于"把这些能力组合成免部署工业测控终端的架构与自包含分发方式"。

## 一、技术问题

传统测控终端是编译型桌面程序（Qt/C++ exe）：需要逐台安装、依赖运行时库、每平台单独构建、版本升级要重新分发安装包；车间电脑还常有无管理权限、离线无网络等约束。部署和升级成本高，且软件的通信逻辑无法在目标环境外自动验证。

## 二、创新点

1. **浏览器原生直连工业硬件的终端架构**：以 Web Serial API 直接访问串口设备，界面、通信状态机、协议处理全部运行在浏览器内，无中间服务、无本地代理进程。

2. **全自包含离线分发**：界面库（Bootstrap 5 及图标）全部**本地化随包分发**（`vendor/` 目录），零 CDN/网络依赖——离线车间环境直接可用；部署即**拷贝一个文件夹/压缩包**，无安装程序、无注册表写入、无管理员权限要求。

3. **零构建、零安装、发文件即用**：纯 HTML/CSS/JS 三件套，无 npm、无编译步骤；`file://` 协议在 Chrome/Edge 下即安全上下文，双击 `index.html` 即可运行（可选本地 HTTP 服务器作为更稳妥的备选）。

4. **权限边界浏览器化**：串口访问授权由浏览器权限模型强制执行（用户手势触发授权弹窗），终端软件自身不再持有无限制的系统权限——面向工控场景的权限收窄。

5. **内置毫秒级通信日志与导出**：所有串口收发、状态机流转、错误带毫秒时间戳记录，支持级别过滤、面板查看与 .log 导出（含未捕获异常）——把现场排障信息变成可分发、可归档的工件（与第 1 点的可验证性呼应）。

6. **架构分层使核心逻辑脱离浏览器可验证**：界面层（DOM 薄层）与数据层（打包/解析/显示计算）、通信层（状态机）强制分离，核心层在 Node.js 下自动回归验证（专利点 1 的承载架构）。

## 三、具体实现方式

### 3.1 系统组成（模块清单）

```
app/
├── index.html          # 连接窗口 + 主界面 + 9 个功能对话框（Bootstrap 模态框）
├── css/style.css       # 自定义样式薄层
├── vendor/             # Bootstrap 5.2.3 + bootstrap-icons（本地化，无 CDN 依赖）
├── js/
│   ├── log.js          # 统一日志模块（控制台 + 环形缓冲 + 页面面板 + 导出）
│   ├── protocol.js     # 组帧/解帧层
│   ├── store.js        # 全局状态 + 数据注册表 + 事件总线
│   ├── serial.js       # Web Serial 管理 + 通信状态机
│   ├── core.js         # 纯数据层（无 DOM，可测）
│   └── app.js + dlg-*.js  # 连接窗口、主界面与 9 个对话框（DOM 薄层）
└── test/               # 177 项等价性回归测试（node 运行，无需浏览器）
```

### 3.2 连接与通信流程

1. 用户点击 Connect（**用户手势**）→ `navigator.serial.requestPort()` 弹出浏览器串口授权窗，选择端口；
2. `port.open()` 按界面设置（波特率/数据位/停止位/校验）打开串口，取得读写流（writer/reader）；
3. 后台读取循环持续收字节 → 100ms 静默窗口聚批 → 流式解帧（专利点 4）→ 驱动状态机（专利点 2）与待决命令匹配（专利点 3）；
4. 所有收发字节与状态流转进入日志模块（毫秒时间戳 + 十六进制帧 + 状态机快照）。

### 3.3 部署与运行方式

- **方式一（最简）**：整个 `app/` 文件夹（或压缩包）发给对方，Chrome/Edge 双击 `index.html` 即用（file:// 属安全上下文，Web Serial 可用）；
- **方式二（推荐稳妥）**：同目录起本地静态服务器（如 `python -m http.server 8080`）后浏览器访问——两者界面与行为完全一致，无构建差异。

### 3.4 现场排障支撑

日志面板可折叠、支持 DEBUG/INFO/WARN/ERROR 级别过滤（也可 `?log=warn` URL 参数或控制台动态切换）；TX/RX 记录完整帧十六进制与状态机快照（`Down/idx/err/msgEnd/msgLen`）；一键导出 .log 文件，含未捕获异常——车间操作工导出日志即可远程定位问题。

## 四、与 C++（Qt 原版）方式的不同点

| 维度 | Qt 原版（C++ 桌面程序） | 本方案（浏览器终端） |
|---|---|---|
| 安装 | 需安装程序 + 运行时库，可能需管理员权限 | **零安装**：发文件夹即用，无需任何权限 |
| 平台 | 每平台单独构建（Windows/Linux 构建链） | 跨平台：任何有 Chrome/Edge 的机器 |
| 构建 | 编译 + 打包 | 零构建：纯三件套直接分发 |
| 网络依赖 | 无 | 无（界面库全本地化，无 CDN） |
| 硬件访问 | 系统串口 API，进程级权限 | Web Serial + 浏览器授权弹窗（权限边界收窄） |
| 更新 | 重新分发安装包 | 替换文件夹/文件即更新 |
| 排障 | 依赖现场复现 | 内置毫秒级日志 + 导出 |
| 核心逻辑验证 | 需编译上机 | Node.js 下 177 项自动回归（无浏览器无真机） |
| 已知风险 | 无浏览器依赖 | 见下表 |

**浏览器方案的风险（来自专利思路.md，说明书"技术效果"一节应如实披露）：**

| 风险 | 说明 |
|---|---|
| 浏览器依赖 | Web Serial 仅 Chrome/Edge 支持；其他浏览器（含国产定制浏览器）不可用 |
| 浏览器升级漂移 | 浏览器自动更新可能改变 Web Serial 行为，版本不受终端软件控制 |
| 误操作 | 误关标签页、多开页面抢同一串口、USB 拔插后需重新走授权流程 |
| 无管理权限环境 | 部分工控机锁死浏览器安装/配置 |

## 五、技术效果

- **免安装、免构建、发文件即用**：部署成本从"逐台安装+版本管理"降为"拷贝一个文件夹"。
- **离线自包含**：无 CDN、无网络依赖，适配无外网的车间环境。
- **跨平台**：Windows/macOS/Linux 只要有 Chrome/Edge 即可运行。
- **可验证**：核心通信逻辑不依赖浏览器与真机即可全量回归（第 1 点），终端质量可 CI 化。
- **可排障**：毫秒级日志导出使远程定位问题成为可能。

## 六、权利要求要点建议

**系统权利要求（独立权利要求，包装第 1–4 点）**：一种基于浏览器的测控终端通信系统，其特征在于包括：
- 串口通信管理模块，运行于浏览器内，通过浏览器串口接口与串口设备建立直接连接，并以多级会话状态机控制交互过程（对应第 2 点）；
- 命令应答匹配模块，以携带期望响应特征集合的待决命令对象实现命令-响应一一对应（对应第 3 点）；
- 流式解帧模块，按静默窗口聚批并消歧短应答与数据帧前缀（对应第 4 点）；
- 一致性验证模块，以三向数据流等价检查验证通信行为与源程序的字节级一致（对应第 1 点）；
- 界面模块与日志模块；
- 系统资源全本地化存储，无需网络即可运行，无需安装与构建即可分发使用。

**未来从属权利要求方向（按专利思路.md 的扩展建议）**：
- 打包形态：以桌面壳（Tauri/Electron）承载同一套前端代码的终端形态；
- 工位化增强：单实例防多开（防止两个实例抢同一串口）、串口断开自动重连、工位全屏锁定；
- 诊断增强：日志自动导出与远程诊断流程。
